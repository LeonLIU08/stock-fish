# 量化交易链路：模块缺口与开发待办

- 状态: 未完成
- 立案: 2026-10-05
- 范围: 不使用杠杆、只做多股票的中低频策略
- 检查方式: 只判断模块是否存在。不审查公式、阈值和成交细节是否正确

对照的链路是：

> 数据 → 候选股票 → 股票评分 → 目标持仓 → 风险检查 → 订单 → 成交与复盘

选股、仓位、执行分开。选股回答“看好谁”，仓位回答“给它多少钱”，执行回答“怎么成交”。

## 1. 八个模块的存在情况

| 模块 | 判定 | 仓库里对应的位置 |
|---|---|---|
| 1. 数据 | 已有 | `market_data/` 负责行情、财务、新闻与多源切换；`analysis/backtest/bars.py` 的 `BarLoader` 负责回测 K 线与磁盘缓存；`qlib-zh/data_runner.py` 负责 Qlib 数据包 |
| 2. 股票池 | 缺失 | 指数名称与当前成分查询在 `market_data/stock_index/` 和 `GET /api/qlib/index-stocks`。回测名单是 `analysis/backtest/ma_cross.yaml` 里的静态 `universe.symbols`。初筛规则写在 `qlib-zh/scripts/practice/stage3_first_screen.py`，属于研究脚本 |
| 3. 信号 | 链路模块缺失 | 单股综合分在 `analysis/scoring.py`。单标的买卖列在 `analysis/backtest/signals.py` 与 `strategies/ma_cross.py`。模型预测在 `qlib-zh/infer_runner.py`。大师意见在 `analysis/agents/`。没有面向股票池、带有效期、交给组合构建的截面信号模块 |
| 4. 组合构建 | 缺失 | 大师订单里的 `position_size_pct` 是单股建议。`analysis/batch_analyzer.py` 产出的是批量分析摘要。`qlib-zh/scripts/small/stage3_live_topk.py` 在研究脚本里做 top-K 等权。`analysis/backtest/todo/003` 规划的是共享现金账本，权重计算不在其中 |
| 5. 风险管理 | 组合层缺失 | `analysis/agents/risk_manager.py` 对单只股票给出下行风险意见和软否决。`qlib-zh/scripts/practice/stage4_risk_eval.py` 给个股打财务、估值、风险标签。没有检查集中度、行业暴露、杠杆并改写目标权重的模块 |
| 6. 交易执行 | 缺失 | `analysis/backtest/engine.py` 在单标的回测里按信号假设成交。没有把目标仓位变成订单，并管理下单、撤单与未完成数量的模块 |
| 7. 回测评估 | 已有 | `analysis/backtest/`：单标的独立账户、成本、收益与回撤、报告。组合账本仍是 `analysis/backtest/todo/003`、`004`，状态为未完成 |
| 8. 实盘监控 | 缺失 | 飞书机器人推送分析结果。`GET /api/config/health` 检查数据源。`memory/masters/` 记录大师预测准确率。没有持仓、成交和模拟偏差的监控 |

已有模块不在下面重开。数据模块继续负责取数、清洗和存储。回测模块继续负责用历史数据检验收益、风险和成本；共享资金账本仍按 `analysis/backtest/todo/` 推进，本文不改那份规格。

`qlib-zh/scripts/practice/` 里的六段研究脚本可以以后被新模块读取，待办不要求把这些脚本改造成系统模块。

## 2. 开发顺序

```text
股票池 → 截面信号 → 组合构建 → 组合风险检查 → 交易执行 → 实盘监控
```

后一个模块依赖前一个模块的输出。回测在信号、目标和执行记录可用之后接入，用于检验整条链；接入方式沿用现有回测入口，不另建第二套回测框架。

每个待办的完成定义都是：模块存在，输入输出边界清楚，能被上下游调用。具体评分公式、优化器和券商协议留到单独立项。

## 3. 待办

### 3.1 股票池模块

- 状态: 未完成
- 职责: 在某个日期决定哪些股票允许进入后续评分和交易
- 输入: 市场或指数范围、流动性、上市时长、可交易状态等过滤条件，以及查询日期
- 输出: 该日期的候选股票列表
- 依赖: 现有数据模块
- 完成定义:
  - [ ] 有独立模块，主流程和回测都能按日期取到候选列表
  - [ ] 回测使用的是该历史日期当时的池。今天的成分名单不能直接当作十年前的池
  - [ ] 静态 YAML 名单仍然可以作为人工指定的池，过滤规则与手工名单都能进同一输出格式

### 3.2 截面信号模块

- 状态: 未完成
- 职责: 对股票池形成投资判断，把“看好谁”和“何时重新选”写成可传递的结果
- 输入: 某一日期的股票池，以及该日期当时已经可用的行情与财务数据
- 输出: 每只股票的评分或预期收益、方向、置信度、信号有效期；以及下一次更新选择的时点
- 依赖: 股票池模块。计算可以调用现有 `ScoringEngine`、规则策略或 Qlib 推理
- 完成定义:
  - [ ] 有独立模块，输出能直接交给组合构建，调用方不需要再从分析报告或 K 线信号列里摘字段
  - [ ] 信号带有生成时点和有效期。调仓时点是模块输出的一部分，例如“收盘后计算，下一交易日执行”这类规则有明确字段
  - [ ] 单股分析页、均线回测策略、大师委员会保持原职责。本模块消费它们的判断，或另行计算截面分数

### 3.3 组合构建模块

- 状态: 未完成
- 职责: 把信号和资金预算变成各股票的目标权重、目标市值，再减去当前持仓市值，得到计划交易金额
- 输入: 截面信号、账户总资产、股票投资预算或现金保留比例、当前持仓市值
- 输出: 每只股票的目标权重、目标市值、计划买入或卖出金额。正数买入，负数卖出，目标权重为 0 表示清仓
- 依赖: 截面信号模块，以及一份当前持仓。持仓在执行模块落地前，可以用手工持仓或回测账本读数
- 完成定义:
  - [ ] 有独立模块。账户层先决定股票预算，再决定单票目标，最后用“目标市值 − 当前市值”得到计划交易金额
  - [ ] 至少包含等权分配。按评分分配、按波动率倒数分配、组合优化可以作为同一模块里的可替换方法，第一版不必全部实现
  - [ ] 卖出金额可以出现在仍然入选的股票上，表示持仓高于目标，需要降回目标
  - [ ] 大师 `position_size_pct` 和批量分析摘要继续服务研究报告。它们的数字只有在被显式送入本模块时才成为目标权重

### 3.4 组合风险管理模块

- 状态: 未完成
- 职责: 检查目标权重的集中度、行业暴露和杠杆，必要时改写目标，再交回组合结果
- 输入: 组合构建产生的目标权重，以及股票所属行业、账户是否允许杠杆等约束
- 输出: 调整后的目标权重，以及被削减的股票或行业说明
- 依赖: 组合构建模块
- 完成定义:
  - [ ] 有独立模块，位于目标仓位之后、订单之前
  - [ ] 能表达单票上限、行业上限、只做多、不使用杠杆。超限时输出调整后的目标，原始目标保留可追溯
  - [ ] 现有单股风险经理继续负责单票下行意见和软否决。组合模块读取约束和权重，个股意见可以作为后续的一项输入，第一版不要求接通 LLM

### 3.5 交易执行模块

- 状态: 未完成
- 职责: 把风险检查后的目标仓位变成订单，跟踪下单、撤单、部分成交，并用成交更新持仓
- 输入: 调整后的目标权重或计划交易金额、当前持仓、未完成订单
- 输出: 订单（方向、数量或金额、价格方式）和成交记录。计划金额与最终成交金额分开保存
- 依赖: 组合风险管理模块的目标，以及当前持仓与未完成订单
- 完成定义:
  - [ ] 有独立模块。订单生命周期与回测引擎里的“信号出现后假设成交”分开
  - [ ] 能表达差额过小则跳过、大单拆开、已有未完成订单时按剩余数量下单、成交后重算剩余差额
  - [ ] 第一版的成交可以是模拟成交，供回测和纸面账户使用。真实券商通道作为本模块的后续适配，不在第一版完成定义里

### 3.6 实盘监控模块

- 状态: 未完成
- 职责: 对照目标持仓、订单、成交和实际持仓，发现偏差与异常
- 输入: 目标权重、订单、成交、实际持仓，以及回测或模拟在同一段时间的结果
- 输出: 持仓与成交核对、交易偏差报告、异常告警
- 依赖: 交易执行模块产生的订单与成交。模拟阶段先对照纸面账户
- 完成定义:
  - [ ] 有独立模块，能回答当前持仓是否接近目标、哪些订单未完成、模拟路径与实际路径差在哪里
  - [ ] 告警覆盖未成交超时、持仓偏离目标、重复下单这类交易异常
  - [ ] 飞书分析卡片、数据源健康检查、大师预测准确率保持原职责

## 4. 本清单不做

- 不重写 `market_data/`，不把公司行动或缺失值处理从数据模块里拆出新系统。股票池若需要历史成分和可交易状态，向数据模块要按日期可取的数据。
- 不重写 `analysis/scoring.py`、大师委员会、`analysis/backtest/` 的单标的引擎。
- 不在这里实现组合优化的协方差、风险厌恶和成本惩罚，也不规定第一版用哪一组因子系数。
- 不把 `analysis/backtest/todo/003`、`004` 的账本和 `size_order` 规格并进本文。组合构建负责目标权重和计划金额；003 的账本负责给定数量后的现金、持仓和净值。
- 不接入实盘券商，不使用杠杆，不做空。
