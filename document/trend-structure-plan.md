# 趋势线与趋势区间开发计划

- 状态: 未完成
- 立案: 2026-10-05
- 依据: 多尺度线段结构匹配引擎设计（收盘价、因果拐点、边界对象、生命周期）
- 完成定义: 对指定股票的一段已完成 K 线，输出一份可离线打开的 HTML。页内包含可缩放、可平移的收盘价走势、趋势线和趋势区间，以及统计与拟合误差。图和统计读同一份快照。

本计划只安排第一版能交付的趋势线拟合。形态模板（双顶底、头肩、旗形等）留作同一引擎上的后续模板，不在本计划实现。

## 1. 仓库里已经有什么

当前没有拐点、线段、趋势线或形态识别实现。和本计划相关的现有能力是：

| 现有位置 | 可复用的部分 | 不带入识别引擎的部分 |
|---|---|---|
| `analysis/backtest/bars.py` 的 `BarLoader` | 港股 / 美股已完成 K 线，Longbridge → Yahoo → AkShare，磁盘缓存 | 开高低、成交量、复权细节的解释权 |
| `analysis/backtest/charts.py` | 深色配色可作 HTML 样式参考 | 不复用。回测图是 matplotlib 静态 PNG，不能在页内缩放和平移 |
| `analysis/backtest/report.py` | JSON 落盘方式 | 不复用其 Markdown / HTML 模板。那份报告写的是收益、回撤、夏普 |
| `tests/test_ma_backtest.py` | `unittest` + 合成收盘序列，不依赖网络 | 账户、成交、策略插件 |
| `scripts/run_backtest.py` | YAML + 命令行入口的用法 | 策略、成本、基准 |

回测计划 `analysis/backtest/todo/` 里的 003、004 仍未完成。本计划不改账本、策略和下单。

识别引擎放在新目录 `analysis/structure/`。它只接收已经结束的 K 线，只读取时间戳和收盘价。取数脚本可以调用 `BarLoader`，把结果裁成标准序列后再进入引擎。

## 2. 第一版交付

一次运行对应一个标的、一个 K 线周期、一份参数版本、一种价格轴。产出目录：

```text
structure_results/{symbol}/{interval}/{param_version}/{price_axis}/{data_hash}/
  snapshot.json    引擎唯一结构化结果，供测试和复现
  report.html      给人看的唯一交付物，内嵌同一份快照
```

`price_axis` 取 `log` 或 `uniform`。同一段收盘价的两种轴各占一个目录。

不生成 `chart.png` 或 `report.md`。`report.html` 是单文件页面：样式、图表插件和快照都写在文件内，双击用浏览器打开，不启动本地服务，也不请求外网。

`data_hash` 覆盖时间戳序列和收盘价。复权、补数或历史价格修订会落到新目录，原目录保留。

命令行入口：`python scripts/run_trend_structure.py`。

第一版必须能表达的对象：

- 短、中、长三个尺度的已确认拐点，以及末端尚未确认的临时拐点。
- 相邻已确认拐点之间的基础线段。
- 上升支撑线、下降压力线，以及斜率接近水平的支撑 / 压力。
- 趋势区间：同一尺度上一条下边界和一条上边界包住的有效区段。宽度近似稳定时标为通道；宽度沿序号收缩时标为收敛区间；两条边界都接近水平时标为横向区间。
- 每条线和每个区间的生命周期：候选、已验证、被收盘价突破、过期。
- 页内统计表中的样本统计和拟合误差。评分表示规则下的吻合质量，不表示后续上涨概率。

图上默认画中尺度的已验证线和区间；短、长尺度用线型区分，可用图例打开。备选解释进页面附录，不全部叠到主图上。

## 3. 本计划不做

- 双顶、双底、头肩、三角形、楔形、旗形的模板匹配，以及 DTW 相似搜索。
- 成交量、ATR、盘中最高最低、盘中穿越。
- 把突破事件当成可成交的买卖指令，或接入 `analysis/backtest` 的账户引擎。
- 实时推送。引擎按“每根已完成 K 线输入一次”设计，第一版只提供历史逐根回放。
- 从低周期 K 线自行聚合高周期。周期收盘价由现有行情加载负责。
- 改动主站 `static/index.html`。本计划的页面是每次运行单独生成的 `report.html`。
- 在一种价格轴上拟合，再换到另一种价格轴上把边界画成直线。`price_axis` 一旦选定，波动、拐点、拟合、评分和页面纵轴使用同一坐标。

三角形、楔形、箱体以后走设计文档里的双边界模板。第一版的通道、收敛区间、横向区间只是边界对的几何标签，供看图和写报告，不带交易含义。

## 4. 先冻结的四项契约

阈值可以调，下面四条在第一版里不能随实现方便而改变。参数整包带版本号，写入每条结果。

### 4.1 拐点何时确认，确认后能否修改

每个尺度单独维护一段状态：找高点，或找低点。

- 找高点时，候选高点始终是本段至今的最高收盘价位置。
- 收盘价从该候选反向回撤，回撤达到本段门槛，确认这个高点，然后转入找低点。下降段对称。
- 进入新的一段时，用当时已经算好的波动尺度固定本段门槛。段内候选极值可以移动，门槛不随后续波动改写。
- 确认之后，该拐点的极值位置、价格和确认时间不再修改。新 K 线只允许新增拐点和更新末端临时结构。
- 相同收盘价连续出现时，极值时间取这段平台的最后一根。
- 末端尚未达到反向门槛的一段标为临时线段，不参与已验证趋势线和趋势区间。

三个尺度互不要求“长尺度拐点必须是短尺度拐点的子集”。确认完成后再记录谁的时间范围覆盖谁，这条关联不反过去改确认结果。

每个拐点保存三个时间：

| 时间 | 含义 |
|---|---|
| 极值时间 | 最高或最低收盘价所在的那根 K 线 |
| 确认时间 | 反向变化达到门槛的那根 K 线 |
| 系统可用时间 | 引擎第一次可以使用该确认结果的时间 |

历史回放里，系统可用时间等于确认时间所在的那根已完成 K 线。回放和以后的实时入口都读这个字段，避免把“价格曾经到过”写成“当时已经知道”。

### 4.2 哪些小波段可以忽略

第一版的趋势线只使用已确认拐点，不把多条基础线段合并成一条匹配线段。

基础线段全部保留。一条支撑或压力要成为已验证边界，中间已确认的同类拐点必须参加接触或破坏检验。出现明显落到边界错误一侧的拐点时，这条候选不能标为已验证。

“一段趋势内部有小回撤，仍可看成一条大波段”留给以后的匹配线段。那一层要单独记录被忽略的内部波动和惩罚。第一版不打开这层，避免趋势线为了贴合而跨过破坏点。

### 4.3 硬约束、软评分、突破三者分开

硬约束不通过的对象停在候选或拒绝，不能靠其他分项补成已验证。

趋势线的硬约束包括：至少两个同类已确认拐点、斜率符号符合角色、有效跨度内的最大破坏深度不超过门槛、没有跳过已确认的破坏拐点。

趋势区间的硬约束包括：上下边界在有效序号区间内宽度为正、两侧各自达到最少独立接触、平行或收敛关系符合其几何标签。

软评分只给已经通过硬约束的对象，分项见第 8 节。报告同时给总分和分项。

突破是之后的生命周期事件：收盘价落到边界错误一侧，深度超过缓冲，并连续达到规定根数。它不改写“结构曾经成立”的快照。

### 4.4 结果何时真正可用

事件时间不得早于该事件所需全部拐点的系统可用时间。

价格可以在更早的 K 线上已经越过边界。报告可以把这记为价格事实。可引用的结构事件仍写在信息齐备的那一根上。

结构成立时冻结快照：关键点、边界参数、当时的容差、评分、相关确认时间。之后若出现另一组更合适的拐点，写成新修订，旧修订保留。已发布事件不回写。

同一数据版本、同一参数版本、同一输入前缀，历史整段回放、逐根回放和中途重启后续跑，得到相同的快照。

## 5. 模块与目录

模板匹配层在本计划中是空的扩展点。趋势线不在作图层里重新拟合。

```text
analysis/structure/
  config.py        参数版本与默认阈值
  series.py        标准序列：序号、对数价格、间断标记
  volatility.py    截至当前的收益率波动尺度
  pivots.py        三尺度因果拐点
  segments.py      基础线段与临时线段
  boundaries.py    支撑 / 压力候选、误差、去重
  zones.py         上下边界配对成趋势区间
  lifecycle.py     状态、冻结快照、事件
  snapshot.py      汇总为唯一 JSON 快照
  view_model.py    把快照换成价格坐标上的点列，不重新拟合
  assets/
    echarts.min.js      随仓库提供的图库，生成时内嵌进 HTML
    structure-chart.js  图表插件：挂载、缩放、平移、复位、悬停
  html_report.py   只读快照，写出单文件 report.html
scripts/run_trend_structure.py
tests/test_trend_structure.py
```

建议的调用方向：

```text
BarLoader 或合成序列
    → series
    → volatility + pivots + segments
    → boundaries + zones
    → lifecycle
    → snapshot.json
         → view_model
         → report.html
              ├→ 统计表（直接读内嵌快照）
              └→ structure-chart 插件（只读 view model）
```

`view_model.py`、`structure-chart.js` 和 `html_report.py` 不调用拐点或拟合函数。检验方式：测试里直接构造快照，仍能生成 HTML，且页面里不会多出快照中没有的线。

图表插件的页面接口保持很小：

```text
TrendChart.mount(container, viewModel) → { reset, destroy }
```

`viewModel` 带 `price_axis`，以及该坐标下的收盘价点、拐点、线段端点、边界斜率和截距、区间色带上下沿。插件按这个字段设置纵轴，边界在所选坐标里画成直线。悬停始终显示实际股价。用户缩放或平移时，插件只改可视窗口，不重算斜率和截距。以后若更换图库，只替换 `structure-chart.js`，快照和 view model 不动。

## 6. 数据口径

### 6.1 标准序列

引擎输入是按时间排好的已完成 K 线，字段只有时间戳和收盘价。`price_basis` 固定为 `close`。

几何横轴是有效 K 线序号，从 0 递增。周五到周一在日线上相隔一根。时间戳只用于显示、事件记录和间断判断。

价格轴由配置项 `price_axis` 选择，默认 `log`。命令行用 `--price-axis log` 或 `--price-axis uniform` 覆盖。一次运行只读这个值，并写入每条边界和快照身份。

| `price_axis` | 几何坐标 | 页面纵轴 | 图上的趋势线 |
|---|---|---|---|
| `log` | \(x_t=\ln C_t\) | 对数，刻度文字为实际股价 | 直线 |
| `uniform` | \(x_t=C_t\) | 均匀，相同价差对应相同距离 | 直线 |

对数轴上，100 到 200 的距离等于 200 到 400。均匀轴上，100 到 110 与 400 到 410 一样长。两种结果都保留，默认用对数，因为趋势比较的是相对涨跌。

`log` 时，插件使用对数纵轴，直线连接边界的两个实际股价端点。`uniform` 时，插件使用均匀纵轴，直线连接同一对端点。切换配置要整段重跑，页面不负责把对数拟合改画到均匀轴上。

### 6.2 间断

不把停牌或缺失填成相同收盘价。

- 日线序列里本来没有周末和普通休市，这些空隙不构成间断，也不拉宽斜率。
- 相邻两根的间隔大于该周期的间断门槛时，记一个间断，数据质量降级。日线按交易日计，第一版用“大于 5 个交易日”（周一至周五；周末不计入，交易所假日这一版仍算交易日）。分钟线用“大于中位间隔的 3 倍”。
- 候选拐点段、趋势线和趋势区间都不得跨越间断。
- 现有 `BarLoader` 不区分停牌和行情缺失。第一版把超阈值缺口统一记为间断。等行情源能提供交易日历后，再拆成停牌和缺失两种质量标记。

### 6.3 波动尺度

收益率 \(r_t = x_t - x_{t-1}\)。波动尺度 \(s_t\) 由截至当前的收益率平方的指数加权平均再开方得到，只使用当前和过去。

规则：

- \(s_t\) 有下限，连续相同收盘价时门槛不到零。
- 更新波动估计时，可以对单根极端收益设上限，减轻异常值把后续门槛抬太高。
- 原始收盘价保持不动。极值和边界破坏仍用原始跳变，不用截断后的收益代替价格。

尺度 \(j\) 的反转门槛：

\[
\delta_j = \max(k_j s,\ \delta_{\min,j}), \quad k_{\text{短}} < k_{\text{中}} < k_{\text{长}}
\]

这里的 \(s\) 是进入该段时已经固定下来的值。

### 6.4 与回测加载的边界

`scripts/run_trend_structure.py` 复用 `BarLoader` 的代码、周期和缓存。进入 `series.py` 之前丢掉 open、high、low、volume。引擎不读取 `analysis/backtest` 的策略、成本和账户。

A 股若走现有日线数据源，同样只留下时间戳和收盘价。几何代码不按市场分叉。

## 7. 分阶段实施

前一阶段的测试未通过时，不开始依赖它的下一阶段。作图放在快照字段冻结之后。

### 阶段 0：参数、标准序列、运行身份

- [x] `config.py` 写出参数版本 `structure-params-v0` 和第 9 节的默认值。
- [x] `series.py` 按 `price_axis` 把输入变成序号、时间戳、收盘价、几何价格、间断标记、`price_basis`、`price_axis`、`data_hash`。
- [x] 拒绝非正收盘价；不向前填充缺口。
- [x] 输出目录包含参数版本和 `data_hash`，重复运行同一输入覆盖同一目录的同名文件，不同数据不互相覆盖。

验收：同一收盘序列两次构建，`data_hash` 相同；改一根收盘价后哈希变化；插入一个超阈值日历缺口后，该处有间断标记，序号仍然连续，中间没有被造出来的横盘 K 线。

### 阶段 1：因果拐点

- [x] 三个尺度各自的状态机，门槛在段初固定。
- [x] 拐点记录角色（高 / 低）、尺度、极值序号、确认序号、三个时间、价格、所用门槛。
- [x] 临时末端与已确认拐点分开存放。
- [x] 同价平台的极值时间取最后一根。
- [x] 提供“喂到第 T 根为止”的结果，供前缀比较。

验收见第 10 节的前缀一致性、确认不回写、噪声稳定和多尺度稳定。这一阶段是后面所有图的时间语义，阈值好看与否不是验收条件。

### 阶段 2：基础线段

相邻两个已确认拐点构成一条基础线段。保存：起止拐点、方向、跨越根数、所选坐标中的涨跌幅、涨跌幅相对段初波动尺度的倍数、在序号–几何价格坐标上的斜率、内部收盘价到端点连线的最大偏离、内部逆向波动、尺度、确认时间。`log` 下的涨跌幅是对数收益，`uniform` 下是价格差。

临时末端单独标记，不进入边界候选的端点集合。

事后关联：一条长尺度线段的序号范围内包含哪些中尺度线段，中尺度包含哪些短尺度线段。关联失败不回改拐点。

验收：线段数等于该尺度已确认拐点数减一；临时末端存在时不计入这个等式；线段的确认时间等于其终点拐点的确认时间。

### 阶段 3：趋势线

候选生成：

- 只用同一尺度、同一角色、同一连续无间断区段内的已确认拐点。
- 两个同类拐点确定一条候选。再向时间前方和后方收集落在最大观察长度内的其他同类拐点，做接触和破坏统计。
- 搜索受最大序号跨度、最大拐点个数约束。不从全历史任意抽点。
- 第一版不做 RANSAC。两点定线之后，只允许在未破坏硬约束的接触拐点上对斜率和截距作小幅调整，调整后用原始收盘价重算接触误差和破坏误差。

误差分开计：

- 接触误差：拐点到线的距离。支撑上方较远表示没贴上，不是破坏。
- 破坏误差：价格落到线的错误一侧的深度。支撑看下方，压力看上方。
- 连续贴线的拐点若序号间隔不超过接触簇窗口，只计一个接触簇。
- 同时记录跨度、接触簇个数、穿越次数、最大穿越深度、最长连续越界根数。

去重：同尺度、同角色、斜率和截距都接近、共享大部分接触簇的候选，保留硬约束通过且软评分最高的一条为主结果，其余为主结果的备选解释，不各自产生突破事件。

已验证的硬门槛见第 9 节。两点线可以存在，状态是候选，报告里与已验证线分节。

斜率使用“每个 K 线序号的几何价格变化”，再除以该段固定波动尺度，得到归一化斜率。`log` 的几何价格是 \(\ln C\)，`uniform` 的几何价格是 \(C\)。不用图上的角度。

验收：合成的抬高低点能给出上升支撑；在两个低点之间插入一个深破位低点时，穿过该低点的线不能成为已验证支撑；刚好越过破坏门槛的序列，报告能指出失败的是哪一条硬约束。

### 阶段 4：趋势区间

在同一尺度、同一无间断区段内，将一条下边界候选和一条上边界候选配对。

\[
U(i) = a_u i + b_u, \quad D(i) = a_d i + b_d, \quad W(i) = U(i) - D(i)
\]

\(i\) 是 K 线序号，\(U\)、\(D\) 与当次运行的坐标一致。

有效区间是同时满足这些条件的最长序号段：\(W(i) > 0\)、两侧都有接触簇、没有超过硬破坏门槛的收盘价停留。有效区间之外的延长线可以计算，但状态上属于投影，不属于已成立结构。

几何标签：

| 标签 | 条件 |
|---|---|
| 通道 | 宽度相对变化小，两条归一化斜率差小 |
| 收敛区间 | 有效区间内宽度下降，且终点宽度仍为正 |
| 横向区间 | 两条归一化斜率都接近 0，宽度相对稳定 |
| 其他边界对 | 硬约束通过，但不符合上面三档；保留在快照中，主图默认不画 |

标签是几何分类。报告不把“通道”写成看多或看空。

去重与趋势线相同：同一区段的近重复区间保留一个主结果和若干备选。不同尺度的区间都保留，并记录序号重叠关系，分数不相加。

验收：宽度稳定的抬升上下轨得到通道；末端宽度变成非正的配对不能把交叉之后的序号算进有效区间；上轨近水平、下轨上升时，若尚未实现三角形模板，标签落在收敛区间或其他边界对，不单独发明一套三角形状态机。

### 阶段 5：生命周期

线和区间各自使用这些状态：候选、已验证、已被收盘价突破、过期。不是每个对象都会走完全部状态。

- 已验证：硬约束在该时刻已经满足。冻结当时的边界参数、接触统计、容差和评分。
- 已被收盘价突破：已验证之后，收盘价在错误一侧连续停留达到根数门槛，且深度超过缓冲。缓冲用波动尺度，不用固定价差。
- 过期：有效区间结束后又走过规定根数，仍没有新的验证，也没有突破事件。对象保留，主图不再把它画成当前有效结构。

每个状态变化是一条事件，字段包括：事件时间、系统可用时间、原因、参考收盘价、边界或区间标识、快照修订号。

新数据只追加事件或新修订。`available_time` 早于某时刻的事件在后续 K 线上保持原样。

本阶段不生成买卖单，不假设能以信号当根收盘价成交。

### 阶段 6：快照、HTML 页面、图表插件、命令行

- [ ] `snapshot.py` 汇总第 8 节的各组信息。
- [ ] `view_model.py` 只读快照，输出 `price_axis`、端点、斜率和截距。端点价格写实际股价。
- [ ] `structure-chart.js` 按 `price_axis` 切换对数或均匀纵轴，并提供挂载、滚轮缩放、拖拽平移、复位和悬停。
- [ ] `html_report.py` 把快照、view model、样式和插件内嵌进 `report.html`。
- [ ] CLI 参数：标的、周期、起止或回看年数、`--price-axis`、要画的尺度、`--as-of`。
- [ ] `--as-of` 只显示系统可用时间不晚于该时刻的拐点、线和区间。用于对照最终页面，检查有没有把后来才确认的结构画到过去。

图例注明当前是“对数价格”或“均匀价格”。趋势线和区间边界在所选纵轴上是直线。悬停气泡中的价格写实际股价。缩放后直线仍然是直线。

页面布局：上方是身份和阅读约定，中间是图，下方是第 8 节的统计表。深色底在页面 CSS 里定义，不从回测 matplotlib 样式借用。

作图要素：

- 只画收盘价折线，不画高低影线，避免把未参与计算的价格画成结构的一部分。
- 横轴位置是 K 线序号，刻度文字是日期。周末不会在日线图上拉出空白档。
- 已确认拐点实心，临时拐点空心。悬停时同时显示极值时间和确认时间。
- 已验证边界用实线，只覆盖其有效序号；向未来的投影用虚线，并在图例写明投影。
- 趋势区间用半透明色带覆盖有效区间。通道、收敛、横向用不同颜色。
- 被突破的边界保留到突破序号，突破点单独标记。
- 主图默认中尺度。短、长尺度用线宽和线型区分，图例点击可以单独开关。

图表插件要支持的基础操作：

| 操作 | 行为 |
|---|---|
| 滚轮 | 以指针所在的序号和价格为中心缩放 |
| 按住拖拽 | 沿序号和价格平移 |
| 底部滑块 | 选择可见的序号区间，拖动两端改变窗口 |
| 双击或“复位” | 回到全部 K 线的初始视窗 |
| 悬停 | 显示该序号的日期、收盘价；命中拐点或边界时显示其角色、尺度和状态 |
| 图例点击 | 显示或隐藏一条序列，不改变快照 |

缩放后的曲线仍使用 view model 里的逐根价格。视窗变窄时不要改成两个端点之间的直线。

## 8. 页面中的统计内容

`report.html` 里的表格与 `snapshot.json` 使用同一批数字。页面至少包含以下各节。

### 身份

标的、周期、起止时间、参数版本、数据哈希、`price_basis`、`price_axis`、引擎代码版本（git 短哈希，取不到则为空并注明）。

### 数据质量

K 线根数、间断次数和间断位置、被拒绝的非正价格根数、质量等级。有间断时写明哪些结构和间断无交叉。

### 波动与门槛

各尺度的 \(k\)、\(\delta_{\min}\)、样本内 \(s_t\) 的中位数、实际使用门槛的中位数。便于解释“为什么这一根确认了拐点”。

### 拐点与线段统计

每个尺度：高点数、低点数、确认延迟（确认序号减极值序号）的中位数和最大值、基础线段数、线段跨越根数的中位数、坐标涨跌幅绝对值的中位数。`log` 时这列是对数收益，`uniform` 时是价格差。

### 趋势线明细

每条主结果一行，备选放附录：

- 标识、修订号、尺度、角色、状态
- 起止时间与序号
- 归一化斜率
- 独立接触簇数、序号跨度
- 接触误差中位数和 P90，单位是该段波动尺度
- 最大破坏深度、最长连续越界根数
- 硬约束逐条通过或失败
- 软评分总分与分项

软评分分项：几何吻合、接触质量、相对波动的显著性、路径完整性、时间跨度、简化惩罚。第一版趋势线没有“忽略内部线段”的合并，简化惩罚记为 0，字段照样输出，方便以后匹配线段接入。上下文吻合在第一版记为“未使用”。

### 趋势区间明细

- 上下边界标识、几何标签、状态、有效区间起止
- 起始宽度、结束宽度、宽度变化比例
- 斜率差 \(|a_u - a_d|\)
- 上下两侧接触簇数
- 区间内最大破坏深度
- 硬约束结果、软评分总分与分项

### 事件

按系统可用时间排序。列：事件类型、可用时间、参考收盘价、对象标识、修订号、原因。若价格更早越过边界，另起一列“价格越过序号”，与事件序号分开。

### 关系

同尺度去重组、跨尺度序号重叠、主结果与备选。不同尺度重叠时写明“不合并为一条证据”。

### 阅读约定

页面开头用一段固定说明：分数是当前参数下的拟合质量；突破是收盘价相对边界的状态变化；本页面不给出成交价格和持仓建议。

## 9. 第一版默认参数

这些数字写入 `structure-params-v0`，用来让规则可运行、可复现。验收看规则是否按契约执行。后续只允许以新版本号调整，不覆盖旧运行目录。

| 参数 | 默认 | 作用 |
|---|---|---|
| `price_axis` | `log` | `log`：几何与纵轴用 \(\ln C\)；`uniform`：几何与纵轴用 \(C\) |
| 波动 EWMA 跨度 | 20 根 | 估计 \(s_t\) |
| 波动收益截断 | 进入估计前，单根 \(\|r\|\) 不超过当时 \(4s\) | 只影响后续 \(s\)，不改价格 |
| \(k\) 短 / 中 / 长 | 1.5 / 3 / 6 | 反转门槛倍数 |
| \(\delta_{\min}\) 短 / 中 / 长 | 0.005 / 0.01 / 0.02 | 门槛下限。`log` 时单位是对数收益；`uniform` 时在每段开始按当时收盘价换成价格差 \(C(\mathrm{e}^{\delta}-1)\) |
| 接触距离 | \(0.5 s_{\text{段}}\) | 算接触，不算破坏 |
| 接触簇窗口 | 3 根 | 近邻贴线并成一簇 |
| 已验证最少接触簇 | 3 | 含两个端点之外至少再有一簇 |
| 硬破坏深度 | \(1.0 s_{\text{段}}\) | 超过则不能已验证 |
| 突破缓冲 | \(0.5 s_{\text{段}}\) | 已验证之后的突破 |
| 突破连续根数 | 2 | 收盘价连续停留 |
| 线的最大跨度 短 / 中 / 长 | 60 / 120 / 250 根 | 限制候选 |
| 单条线最多纳入拐点 | 8 | 限制候选 |
| 通道宽度变化 | 终点宽度 / 起点宽度在 0.8–1.25 | 通道标签 |
| 收敛 | 终点宽度 / 起点宽度 < 0.8，且终点宽度 > 0 | 收敛标签 |
| 横向斜率 | 归一化斜率绝对值 < 0.25 | 横向标签 |
| 平行 | 归一化斜率差绝对值 < 0.35 | 通道和横向都要满足 |
| 过期 | 有效区间结束后 20 根仍无新验证 | 过期状态 |
| 日线间断 | 相邻 K 线交易日间隔 > 5（周一至周五） | 打断候选 |
| 主图最多区间 | 每个尺度 3 个 | 控制叠图；其余在页面附录中 |

`uniform` 的波动 \(s_t\) 用价格差，接触距离、破坏深度和突破缓冲仍是 \(s_{\text{段}}\) 的倍数，含义与 `log` 下的倍数相同。两种轴的测试分开断言。同一收盘序列换轴后必须重跑，旧目录保留。

## 10. 测试

测试放在 `tests/test_trend_structure.py`，用合成收盘序列，不访问网络。形状用文字固定下来，实现时再写成序列。

必须有的用例：

1. **前缀一致性**  
   同一序列一次性算到第 T 根，与逐根输入到第 T 根，已确认拐点、已验证边界和事件列表一致。

2. **确认不回写**  
   在 T 之后追加 K 线，系统可用时间不晚于 T 的事件与边界参数不变。新结构使用新修订号。

3. **平台取值**  
   一段相同最高收盘价，极值序号是平台最后一根。确认发生在随后回撤达到门槛的那一根，而不是平台第一根。

4. **噪声**  
   在已经能确认出中尺度拐点的折线上升落上，加入幅度低于短尺度门槛的扰动。中尺度和长尺度的已确认拐点序号不变。

5. **反例**  
   两个抬高的低点之间，插入一个更深且已被确认的低点。连接两个较浅低点的支撑不得标记为已验证。

6. **容差边界**  
   构造破坏深度刚好不超过硬门槛、以及刚好超过硬门槛的两套序列。前者可以已验证，后者停留在候选或拒绝，报告点名失败约束。再构造宽度终点刚好降到 0 的上下轨，有效区间不包含交叉之后的序号。

7. **多尺度**  
   长尺度一段上升内部增加一个低于短尺度门槛、高于噪声的波动，使短尺度多出一个拐点。长尺度已确认拐点保持不变。

8. **间断**  
   中间抽掉足够长的日历间隔，左右两侧可以各自产生线，没有任何一条线的起止序号跨越间断。

9. **数据修订**  
   修改一根历史收盘价后 `data_hash` 改变。测试只检查身份字段和目录规则，不要求新价格下的几何与旧结果相同。

10. **渲染不重新判断**  
    快照里只有一条已验证支撑时，`report.html` 统计表中的已验证支撑条数是 1，内嵌 view model 里对应的边界也是 1 条。`html_report.py` 和 `TrendChart.mount` 的输入不包含重新拟合的入口。测试解析 HTML，核对内嵌快照，不启动浏览器。

同一条合成序列分别用 `log` 和 `uniform` 跑一遍。两份快照的 `price_axis` 不同，输出目录不同。`log` 页面上 100 到 200 的像素距离等于 200 到 400；`uniform` 页面上相等的是相等的价差。边界在各自纵轴上都是直线。

另外准备四份肉眼检查用的合成页，不作为数值阈值的来源：单边上升后的支撑、平行上升通道、通道末端两根收盘跌破下轨、深破位反例。提交前在浏览器里打开，确认直线、色带和突破标记与快照一致，并实际做一次滚轮缩放、拖拽平移和复位。放大后边界仍是当前价格轴上的直线。

真实行情不进入单元测试。命令行对一只缓存或当场取到的标的做一次冒烟：`00700`、日线、回看 1 年。冒烟只要求跑通并写出 `snapshot.json` 与 `report.html`；不把某一次肉眼满意的线写成永久断言。

## 11. 建议实施顺序

| 顺序 | 阶段 | 完成时可以检查的东西 |
|---|---|---|
| 1 | 阶段 0–1 | 合成序列上的拐点时间，前缀测试 |
| 2 | 阶段 2–3 | 支撑 / 压力和反例拒绝 |
| 3 | 阶段 4–5 | 通道色带的有效区间、突破事件不回填 |
| 4 | 阶段 6 | `report.html` 的图和统计来自同一快照，页内可以缩放、平移、复位 |
| 5 | 冒烟 | 一只真实股票的 `snapshot.json` 与 `report.html` |

阶段 3 结束时已经具备趋势线拟合。阶段 4 补上趋势区间。阶段 6 才算本计划的交付完成。中途不要把未验证候选全部画上主图来“先看到效果”，那会把候选和已验证混成一种图形。

## 12. 以后接到形态模板时不动的部分

以下接口在本计划中就要按这个形状留下，避免以后的双顶、头肩另写一套拐点：

- 已确认拐点带尺度、角色、三个时间，确认后不可变。
- 基础线段全量保留；匹配线段以后另建，并写明合并了哪些线段。
- 边界是独立对象，带接触误差、破坏误差和证据，不只是两个端点。
- 快照修订和事件可用时间由生命周期模块产生，模板只声明自己的硬约束和状态规则。
- 图表插件和 HTML 页面继续只读快照换算出的 view model。更换图库时不改拐点和边界对象。

新增形态时按设计文档增加模板：关键点角色、波段、硬约束和软约束、要用的边界、评分、生命周期、画法。不在模板里重算拐点。
